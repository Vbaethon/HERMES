# HERMES 项目代码图谱

## 何时使用

用户要求更新项目代码图谱时触发。典型触发语句：
- "update"
- "更新图谱"
- "刷新图谱"
- "refresh graph"
- "重新扫描项目"
- "更新代码图谱"

## 更新流程

当用户要求 update 时，执行以下步骤：

### 1. 扫描项目文件

使用 Glob 工具扫描 `Sources/` 下所有 `.swift` 文件，`script/` 下所有脚本。

### 2. 读取所有关键文件

并行读取以下文件（若存在）：
- `Package.swift`
- `README.md`
- `.gitignore`
- `Build/Info.plist`
- `Sources/` 下所有 `.swift` 文件
- `script/` 下所有脚本

### 3. 分析并生成图谱

对每个 Swift 文件分析：
- 文件用途概述
- 关键类型（struct/enum/class/actor）及其作用
- 公开 API 和内部依赖关系
- 代码风格特征（命名约定、设计模式等）

对脚本分析：
- 脚本用途
- 关键变量和参数

### 4. 写入图谱文件

将完整的代码图谱写入 `references/code-graph.md`。图谱应包含：

- **项目概览**：项目名称、用途、技术栈
- **目录结构**：完整文件树
- **文件详细分析**：每个文件的作用、关键类型、依赖
- **数据流图**：主要数据在模块间的流动
- **构建配置**：target 定义、链接框架
- **设计模式**：项目中使用的设计模式和约定
- **修改指南**：常见修改场景的切入点

### 5. 确认完成

向用户报告：
- 扫描了多少个文件
- 图谱是否已写入
- 任何值得注意的变化（如新增/删除文件）

## 图谱使用方式

图谱写入后，后续的代码修改对话中，应先读取 `references/code-graph.md` 获取项目全貌，
再定位到具体文件进行修改。如果用户说 "update" 但图谱已存在且项目无变化，可以快速确认
而非完全重新扫描。

## 重要提醒

- 图谱文件 `references/code-graph.md` 是本技能的核心产出，保持其准确和最新
- 每次 update 应完全重写图谱文件，而非增量更新
- 分析时注意文件之间的依赖关系，特别是 `Models/ImporterModel.swift` 对其他模块的引用
- 记录 UserDefaults key 和持久化机制，这对理解数据流很重要
