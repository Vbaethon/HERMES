# 缩略图缩放 Demo

独立 macOS AppKit 原型，使用公开 API。已确认的 1.9 缩放计算由正式应用和 Demo 共用；Demo 仍不读取正式应用的记录与设置。

当前版本 1.9，更新于 2026-10-06。保留已恢复的焦点缩放、周围叠化、四档
网格及中断交接实现，修正图库起点空位、9 列端缩小阻力和顶部回退导致的
焦点叠化。布局、透明度、原生交接、边界、反向和中断检查共 6355 项通过。

原生性核查以保持这套交互为前提：手势输入使用 AppKit 的
NSMagnificationGestureRecognizer；布局使用 NSCollectionViewLayout 的公开扩展；
动画时钟使用 NSAnimation；图层呈现使用 Core Animation。这些是苹果提供的
原生机制，不应为了改用默认布局而丢掉 Photos 所需的交互逻辑。
网格规划、透明度权重和弹性换算仍是应用代码，不能称为苹果原版源码。
未使用默认 FlowLayout / NSScrollView 整体缩放来替换已认可的交互。

运行 `./Demos/ThumbnailZoom/build.command` 构建，然后打开输出的 `.app`。
运行 `./Demos/ThumbnailZoom/build.command --test` 检查布局、透明度、指针缩放、
切回原生视图、窗口尺寸变化与中断。重新构建前退出 Demo；脚本会拒绝覆盖
正在运行的 Demo。

双指张开放大，双指捏合缩小。四个档位是每行 9、7、5、3 张；拖动窗口边缘时
保持当前列数，缩略图尺寸随可用宽度变化。最小档位停止在 9 列。

新旧档位先完成行列与锚点计算。指针所在焦点行的照片保持不透明，使用同一组
图层连续缩放；这组图片锁定为手势开始时的焦点行，新进入的图片只参与网格
叠化，不会中途变成不透明前景。9↔7、7↔5、5↔3 都使用这一条规则。
没有逐张重新排列动画，也没有松手后的横向回正。图库中部计算好的行起点
在结束后保留，原生集合视图接管选择和滚动。如果计划的前导空格会进入可见
首行，在手势开始前改用完整首行的边界布局。所有档位保留同一个焦点照片索引，
不再将相邻照片换成视觉锚点，源焦点行在边界处也持续不透明缩放。
由中部滚回起点时，清理旧行偏移；第一批图片从首格按顺序展示，
没有通过隐藏、重复或重排媒体来填空。滚动边界限制垂直锚点。
所有网格共用同一个垂直边界修正，避免图库底部出现分离的前景副本。结束时
保留最终叠化画面，等原生单元格完成布局后再交接。

在最大 3 列继续张开时，保留原先逐渐衰减、没有固定伸展上限的弹性。
最小 9 列端采用更强的压缩阻力，持续输入仍有响应，但越捏变化越小，尺寸
渐近于有限的压缩范围，不能一路缩至零；没有达到某个手势值就截断的硬限位。
两端用不同的阻力映射，反向输入立即释放阻力，打断回弹后重新捏合保持当前尺寸。
手势事件直接更新尺寸和周围网格透明度，
手指停住时画面也停住；松手才开始回弹。NSAnimation 在 AppKit 主运行循环
驱动松手和按钮动画，未使用 CADisplayLink。阻力映射是自定义布局所需的
近似实现，回弹曲线参考本机框架默认弹簧参数。

点击“演示”循环查看正常速度；“慢放”以三秒展示相邻档位，便于检查叠化。
实际手势和其他按钮使用正常参数。滚动、点击或开始双指缩放会中止演示。
顶部档位、放大/缩小按钮和键盘 `+` / `-` 也可以切档。动画被快速反向手势
打断时，保留当前网格和缩放中心，避免瞬间改变布局。“显示”菜单中的
“演示边界回弹”（Command-R）可查看当前最近端点的回弹。

构建时只读 `~/Downloads/HERMES/Downloader` 中最多 180 张图片，把缩略预览放入
Demo 自身资源目录。运行时使用这些预览，不读取 Photos 图库、下载记录或设置，
不修改媒体原文件。也可运行 app 内可执行文件并传入 `--images <图片目录>`。

本机系统框架的反推证据、确认范围和近似参数见 `NativePhotosFindings.txt`。
进一步检查确认：原版布局先规划兼容锚点列，再按各布局的锚点 frame 和
归一化缩放中心生成变换；透明度另有统一处理路径。对齐后同一照片为何视觉
上没有叠化感，属于这些调用和用户观察支持的解释；尚未测量完整运行链。
这个 Demo 使用 NSMagnificationGestureRecognizer、NSCollectionView、自定义
NSCollectionViewLayout、CALayer 与 NSAnimation，未链接苹果照片的私有框架。

自动检查验证代码层面的行为，真实窗口的慢放用于确认叠化已呈现。精确曲线、
阻尼、手势跟手性和视觉相似度仍需要与系统照片 App 人工比较。

2026-10-07 正式集成：`Sources/Views/CollectionViews/ThumbnailZoomGeometry.swift`
是四档规划、透明度和端点阻力的共同实现。正式版保留现有边距、格式标记、
选择与原生复制拖出，并只为视口附近的项目保留缩放图层。下载和已完成页面
按批次时间从旧到新显示，每批内保留原始照片索引。下载输入条使用现有
Auto Layout 约束；隐藏进度条不再占位，底部上下使用同一间距，输入条增高
或缩小时，已经滚动到底的视口跟随新的文档底部，其他滚动位置保持原位。

正式版 3.0.0：网格从最新一端计算行起点，首次展示通过原生 NSClipView
滚到文档底部；末行保持完整，不足一行的旧照片保留在最顶部。底部缩放的
四档边界布局在手势开始前一起规划，焦点行仍使用同一组不透明图层连续
缩放。底部视口随文档尺寸改变；浏览旧内容时按媒体身份保留可见位置。
缩放呈现位于集合视图的文档层级内，集合视图持续保持不透明，交接时保留
最终画面和同一位图，避免系统工具栏背景在透明文档与缩放内容之间切换。
工具栏、自动内容边距和滚动边缘效果继续由 AppKit 处理，没有添加背景控件。
首次定位等待集合快照和真实视口可用；系统随后调整工具栏边距时仍保留
原来的底部或阅读锚点，避免页面接入窗口后最后一行落在输入条后面。
采用公开 API 的布局扩展实现所需规则；Demo 1.9 的起点边界仍保留为已确认
交互的回归基线。
