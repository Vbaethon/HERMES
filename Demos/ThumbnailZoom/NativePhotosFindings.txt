macOS 照片缩略图缩放反推记录 — 2026-10-06

环境：本机 macOS 27.0.1 (26A434)。参考用户观察、已安装的 Photos.app
以及本机系统框架。只读分析；没有访问照片图库数据库，没有注入 Photos
进程，也没有在 Demo 中加载或调用私有框架。

从本机依赖、导出符号、Objective-C 元数据和 ARM64e 方法体确认的内容：

1. Photos.app 依赖 PhotosUICore、GridZero、Tungsten 私有框架。
   GridZero 的 PXStepZoomInteraction 有 numberOfZoomSteps / initialZoomStep
   初始化参数，并处理 NSMagnificationGestureRecognizer。
   PXStepZoomInteractionViewModel 有 zoomStep / interactiveZooming 状态。

2. GridZero 中存在独立的 PXZoomablePhotosAlphaAnimator。
   它分别保存目标列索引、呈现列索引、自动淡化状态，并在 _tick 和
   _updateTransitionInfo 中更新。设置中存在 enableAutoCrossfade、
   enableCrossfadeFallback、alphaCrossfadeMinDuration / MaxDuration 等参数。
   这证明该实现有专门的透明度呈现机制；不能据此确认当前界面所有开关的值。

3. PXZoomablePhotosLayout 的 _performAnchorAlignmentVisualShiftWithBaseLayout:
   方法体调用 getBestAnchorColumns:forItemLayouts:startingAtBaseLayout:
   anchorItem:normalizedScaleCenterInAnchor:biasTowardsCenter:，再对其他布局调用
   _performVisualShiftWithLayout:movingItem:toColumn:。
   后者最终调用 shiftItem:toColumn:topPaddingRows:hideIncompleteRows:。
   这是提前选择锚点列、改变网格行起点的具体代码路径，而不是逐项移动动画。

4. _isAllowedToShiftItem:inLayout: 用估计的一屏项目数和
   shiftingRequiredScreensTopDistance 判断是否允许改变行起点。
   如果不能改变，叠化回退分支会采用相邻的视觉锚点项目，索引计算包含
   anchorItem + desiredColumn - currentColumn，并限制在有效项目范围。
   因此不能一概假定每个档位都必须平移整张网格来固定同一张图。

5. _scaleForLayout: 读取相邻布局的列数倒数和行高度来计算缩放。
   _updateZoomTransforms / 其 block 为各子布局读取视觉锚点的 frame 和
   normalizedScaleCenter，设置 CGAffineTransform。
   Tungsten 的 PXGZoomLayout 还保存 primaryLayer、layers、
   anchorObjectReference 和 anchorViewportCenter。

6. 通过 Swift 类元数据只读定位到 PXStepZoomInteraction.addTransition 的
   方法体 0x24CA7EAD8：调用 createAnimation，设置 scope=1、curve=0、
   duration=0.3，再调用 createTransitionWithAnimations。
   后续交互调用 setIsInteractive: 与 setFractionCompleted:。
   这是交互式布局 transition 的代码，不应把它等同于全屏统一淡化。

7. PXZoomablePhotosSettings.setDefaultValues 的方法体和只读常量确认：
   macPinchGestureDampening = 0.5
   pinchSmoothingDuration = 1/30 秒
   sliderSmoothingDuration = 0.2 秒
   rubberBandEffect = 1
   zoomOutRubberBanding = 5，zoomInRubberBanding = 0.5
   zoomSpringStiffness = 150，zoomSpringDamping = 1
   shiftingRequiredScreensTopDistance = 2
   alphaModeTransitionDuration = 0.3 秒
   alphaCrossfadeMinDuration = 0.2 秒，alphaCrossfadeMaxDuration = 1.5 秒
   这些是本机框架初始化的默认值，不能直接当作 Photos 当前运行配置。

8. 本轮进一步解码 147 个相关的 shared-cache Objective-C 调用 stub，确认
   _updateZoom 取得相邻布局并在循环中调用 setAlpha:；_updateZoomTransforms
   的 block 对各子布局读取 visualAnchorAssetReferenceItemByLayout、
   indexPath、frameForItem:，再使用归一化缩放中心与 _scaleForLayout:
   生成变换。透明度与几何是两条处理路径，不能把透明度变化当成重新排布。
   _performAnchorAlignmentVisualShiftWithBaseLayout: 统一规划所有布局，
   也有图库起点、内容移动策略和特定层的回退条件；并非每对列数各写一套动画。

9. Tungsten 的 PXGZoomLayout._configureSublayouts 读取共享的
   anchorObjectReference / anchorViewportCenter，并在子布局循环中分别调用
   setAnchorObjectReference: / setAnchorViewportCenter:。这是父容器共享
   焦点引用和视口中心的实际代码。不能从类名或静态按钮画面推断完整手势曲线。

由 3、5、8、9 和用户实际观察支持的解释：焦点附近相同照片先在两个网格中
对齐；当同一图像、尺寸和位置吻合时，透明度交接在视觉上仍是连续缩放，
周围位置不吻合的图片才明显呈现叠化。这是调用关系支持的解释，尚未通过
逐帧跟踪 Photos 进程的渲染数据直接证明。未确认原版存在 Demo 这种独立
永久不透明的焦点行图层；Demo 使用该公开 API 实现来保持已接受的视觉规则。

实现，不是恢复出的苹果源码，也不能称为全部采用系统默认行为。

已恢复实现的机制：
- NSCollectionView 负责静止布局、选择和滚动；缩放时不插值各项目的 x/y。
- 四套网格在显示前计算完行列、行起点和视觉锚点。
- 行起点在叠化结束后保留，交给原生集合视图；不再横向回正。
- 联合选择四档网格的兼容锚点列，焦点行的同一张照片在两套布局中共享几何。
  动画到达档位时横向偏移自然为零；没有松手后的横向回正阶段。
- 手势开始时的焦点行锁定为一组不透明图层，直接连续缩放。
  新进入的照片只随网格叠化，不随透明度改变重新提升为不透明前景。
  9↔7、7↔5、5↔3 共用这一个规则，没有按档位单独的缩放分支。
  焦点行缩出窗口的照片被裁切；它们在新布局其他行里的副本仍正常叠化。
- 尺寸和周围网格透明度由同一手势进度直接控制，不再用独立时钟追赶输入。
  手指停止时画面停止，反向输入立即反向；不把焦点行整体淡出。
- 带不透明背景的网格容器按正确的 source-over 权重混合，避免中间帧变暗。
- 动画结束时图层和原生网格的 frame、行起点与滚动位置一致。
  最终图层继续覆盖到原生单元格完成布局，避免暴露未完成的布局。
- 所有网格共用垂直边界修正，避免图库首尾的焦点图片因各自夹紧滚动位置
  而形成分离的副本。
- 手势输入采用 0.5 阻尼；大图端没有固定伸展上限，小图端强阻力渐近于有限
  压缩范围，均持续跟手而非硬截断输入。
  松手曲线参考 stiffness=150、damping=1 的临界阻尼参数，不增加列数。
- AppKit 的 NSMagnificationGestureRecognizer 负责输入，NSAnimation 负责
  松手与按钮动画的主运行循环驱动及普通动画曲线，不再使用 CADisplayLink。
- 图库起点第一行不留前导空位；所有布局保留原焦点引用，源焦点行仍持续
  不透明缩放。与正常区域使用同一呈现路径，不按档位分出不同的透明度规则。

2026-10-07 角标时序核对（本机 macOS 27.0.1 / 26A434）：

- GridZero 的 PXZoomablePhotosLayout 保存独立的
  _decorationAlphaAnimator（实例偏移 1240），initWithViewModel: 在
  0x24CA64B48 起以 initWithValue:1 创建，并订阅装饰透明度的变更。
- _updateZoom 的 0x24CA6AFC0–0x24CA6B0A4 读取
  hideBadgesDuringZoom。启用时，zoomState.isAnimating 仍为真，且交互
  正在进行或缩放值偏离 1 至少 0.001，就把装饰 alpha 目标设为 0；
  稳定后设为 1。zoomState 的 +0x38 标志同时由 layout.isAnimating
  方法读取；+0x3a 在 _updateZoomState 中来自 isPinching 与
  isInteractiveZooming 的合并状态。
- 该分支调用 performChangesWithDuration:curve:changes:，地址
  0x24CA6B098 读取 0x24CAAD550 的 float64，独立只读解码结果为
  0.2 秒；curve 参数是私有枚举值 1。尚未确认该枚举对应公开曲线。
- _updateDecorationVisibility（0x24CA6B414）读取 animator 的
  presentationValue 与 value，再经装饰图层的 setAlpha: 更新呈现。
  这条已核对分支未出现独立的固定延迟调用。用户观察到的“结束后
  延迟”与等待布局/弹性动画结束再恢复的机制一致；不能据此编造
  额外固定毫秒数，也未测量 Photos 当前运行实例的实际帧间隔。

本次公开 API 实现：metadata 在手势、回弹、原生视图交接期间保持统一
抑制；交接完成后才用 0.2 秒淡入。不额外加入任意固定延迟。Overlay
每个 grid 的角标共用 decorations 父层 opacity，render 不改这个 opacity；
新进入的层因此不会在缩放中突然显示角标。正式原生 cell 保留 NSTextField
角标与文本，仅由 NSAnimationContext 管理 alpha；重入从 presentation
opacity 取消旧动画，新复用 cell 与异步文字服从相同状态，无图仍隐藏。
淡入/淡出使用公开 easeInEaseOut，属于尚未核实私有 curve=1 的近似。
以上实现不加载、链接或调用 Photos 私有框架。
